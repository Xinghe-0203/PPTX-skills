# 重构计划：保留全部功能、修复 bug、大幅减码

## 基线（已实测，非文档声称）
- **测试**：`tests/` 共 22 个文件、**213 个测试方法，全部通过（238s）**。这是验证基准。重构后必须保持 213/213 通过。
- **代码量**：`pptx_skill/` 65 文件 ~45347 行 + `scripts/` 10 文件 ~5044 行 + `tests/` 22 文件 ~3527 行 ≈ **54000 行**。
- **核心膨胀源**：`pptx_skill/__init__.py`（1406 行）eager re-export 了全部 ~600 个符号；35+ 个扩展模块被 eager import，但绝大多数无内部调用方。

## 重构原则（不可违背）
1. **不删任何模块、不删任何公共函数/类**——扩展能力全部保留（用户明确要求「扩展能力你帮我加入进去」）。
2. **不改任何函数签名**——保持 `from pptx_skill import X` 和 `from pptx_skill.<m> import X` 两条导入路径都可用。
3. **每个可独立验证的小步骤单独 commit**，每步后跑 `python -m unittest discover -s tests`，必须 213/213 通过才进下一步。
4. **先修 bug，后做 lazy 化减码**——bug 修复改的是行为，lazy 化只改加载时机，分开避免混淆。
5. **`scripts/` 暂不迁入包内**（风险大、收益小），只修其 bug。

## 阶段 A：修复已确认的 bug（行为修复，6 个 commit）

### A1. 修复 `__init__.py` 符号冲突与重复 import（纯清理，零行为风险）
- 删除 `__init__.py` 中 `html_import` 的第二次重复 import 块（L460-464）。
- 修复 4 组符号覆盖冲突，采用别名模式（仿 `effects_pt_to_emu`）：
  - `IssueKind`/`IssueSeverity`：`semantic_qa` 版保留原名（QA 管线用它）；`accessibility` 版改别名 `accessibility_IssueKind`/`accessibility_IssueSeverity`，并在 `__all__` 用对应名。
  - `SlideDiff`：`render_qa` 版保留；`diff` 版改别名 `diff_SlideDiff`。
  - `VideoInfo`：`multimedia` 版保留；`video` 版改别名 `video_VideoInfo`。

- **验证**：213 测试通过；`python -c "from pptx_skill import IssueKind; import pptx_skill.semantic_qa as sq; assert IssueKind is sq.IssueKind"` 通过。

### A2. 统一 manifest 写入——让 facade 生成的 deck 同时可被 V2/V3 工具链消费（修 bug #1，最高优先级）
- **根因**：`api.py` legacy 路径写 V3 manifest，但 `ppt_project.load_project` 只读 V2（`sections`/`layouts`）。
- **方案（最小侵入，不破坏 V3 契约）**：让 `ppt_project.load_project` 在读不到 V2 payload 时，若检测到 V3 manifest，从 `manifest.current.content.slides` **降级重建** V2 结构（`sections`/`layouts`），使 `regenerate`/`edit_section` 可用。新增 `_v3_to_v2_project(manifest)` 辅助函数，把 `slides[].elements` 反推为 section dict（title/subtitle/bullets/metrics 等），`layouts` 从 `slide.role` 序列重建。
- `regenerate` 已有的 `zip(sections, content_layouts)` 逻辑保留。
- **验证**：新增测试 `test_facade_roundtrip`：facade 生成 deck → `load_project` 读回 → `edit_section` 改一页 → `regenerate` 成功 → 重新打开验证。跑全套 213 通过。

### A3. 统一 `auto_validate_ppt` 检查项（修 bug #3）
- `api._legacy_validate` 补回 legacy 的「字号层级跳跃」「配色克制」两项检查（从 `pptx_helper.auto_validate_ppt` 移植逻辑），使两套实现返回一致结果。
- 修正「相邻版式重复」警告的页码文本：用 1-based 表述 `第{i-1}-{i+1}页`（i 为 0-based enumerate，实际重复的是 1-based 的 i-1,i,i+1 三页；文本下界应改为 `i`（1-based 首页号）或保持但语义说明「第 X 页起连续 3 页」）。
- **验证**：`assert_eq(legacy_validate(p), facade_validate(p))` 对几个 deck 成立；213 测试通过。

### A4. 修复 `regenerate` 的 layouts zip 错配风险（修 bug #10）
- `regenerate` 中 `content_layouts = [l for l in layouts if l not in {"cover","toc","end"}]`——但 toc 可能因 `len(parsed)>3` 被插入，导致 `content_layouts` 长度 ≠ `sections` 长度。
- 改为：按与 `auto_generate_ppt` 相同的规则重建 `used_layouts`（即重新跑一遍选择逻辑），或更稳妥地：让 `regenerate` 接受 `sections` 时已含 `layout` 字段则直接用，不再依赖 `layouts` zip。
- 实际改法：`for section in sections: layout = section.get("layout") or choose_layout(...)`，不 zip `content_layouts`。
- **验证**：`test_ppt_editing` 通过；新增「toc 插入场景」regenerate 测试。

### A5. 修复 `preview_renderer` auto 模式丢失真实错误（修 bug #20）
- `render_preview` 在 LibreOffice 失败转 COM、或两者都失败时，把 `render_with_libreoffice`/`render_with_com` 返回的 `result.attempts` 累加进最终返回值，而非用 `"not found or failed"` 覆盖。
- **验证**：`test_preview_renderer` 通过；构造 LibreOffice 不存在场景，断言 `attempts` 含具体错误。

### A6. 修复 pixabay 硬编码 key + 文档入口错误（修 bug #19、#2）
- `pixabay_search.DEFAULT_API_KEY` 改为读 `os.environ.get("PIXABAY_API_KEY", "")`，去掉明文 key。
- `SKILL.md` L156 与 `references/engine-api.md` L132 的 `from pptx_helper import auto_validate_ppt` 改为 `from pptx_skill import auto_validate_ppt`（包外唯一可用入口）。
- **验证**：`grep -r "56736282" .` 无结果；213 测试通过。

## 阶段 B：`__init__.py` lazy 化减码（1 个大 commit，分步验证）

### B1. 把 ~35 个扩展模块从 eager import 改为 `__getattr__` lazy 加载
- 用脚本扫描 `__init__.py` 现有 `from pptx_skill.X import (a, b, c)` 块，为每个**非核心**模块生成 `符号 → 模块名` 映射，写入新的 `_LAZY_IMPORTS: dict[str, str]`。
- **核心模块保持 eager**（被 `api.py`/`generation_pipeline.py`/`manifest.py` 等内部依赖或 SKILL.md 主工作流）：`api`、`content_model`、`content_adapter`、`manifest`、`generation_pipeline`、`deck_planner`、`layout_engine`、`pptx_renderer`、`preview_renderer`、`render_qa`、`semantic_qa`、`repair_engine`、`visual_qa`、`golden_renders`、`text_metrics`、`pagination`、`image_crop`、`design_schema`、`template_compiler`、`template_v2_adapter`、`reference_adapter`、`visual_rebuild`、`qa_dataset` + 8 个 legacy `scripts/` 模块 + `transitions`（被 `pptx_renderer` 调用）。
- **扩展模块改 lazy**（~35 个）：`animations`、`watermark`、`sections`、`slide_master`、`image_optimize`、`comments`、`diff`、`export`、`html_import`、`smartart`、`vba`、`table_styles`、`effects`、`connectors`、`protection`、`accessibility`、`metadata`、`equations`、`multimedia`、`groups`、`zoom`、`morph`、`transitions_ext`、`batch`、`svg_import`、`ocr`、`chart_edit`、`color`、`layout_sync`、`markdown_export`、`video`、`svg_export`、`template_downloader`、`merge`。
- 新 `__getattr__`：`if name in _LAZY_IMPORTS: mod = import_module(_LAZY_IMPORTS[name]); val = getattr(mod, name); globals()[name] = val; return val`，cache 后下次直接命中。
- 删除对应的 ~640 行 eager import 块，`__init__.py` 从 1406 行降到 ~450 行（保留核心 eager + `__all__` + `__getattr__`）。
- **注意**：测试用 `from pptx_skill.animations import X`（子模块直导入），不受 `__init__` lazy 影响；`from pptx_skill import X`（包级）走 `__getattr__` 仍可用。
- **验证**：213 测试通过；`python -c "import pptx_skill; from pptx_skill import apply_animation"` 可用；`python -X importtime -c "import pptx_skill"` 显示导入时间显著下降。
